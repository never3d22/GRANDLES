# GRANDLES

Пример автономного REST API, который можно использовать в качестве основы для мобильного или веб-приложения заказов, работающего поверх каталога MODX. Сервер не требует внешних зависимостей и запускается на Node.js, отдавая данные о категориях, товарах и вариантах получения заказа.

## Возможности

- Категории и товары с фильтрацией по категории и наличию.
- Варианты получения: самовывоз и доставка с тарифами.
- Создание заказа без онлайн-оплаты: подсчет корзины, проверка наличия и стоимости доставки.
- Простая CORS-настройка для связи с клиентским приложением или фронтендом в MODX.

## Структура API

| Метод | Маршрут | Описание |
|-------|---------|----------|
| `GET` | `/api/health` | Проверка доступности сервера. |
| `GET` | `/api/categories` | Список категорий каталога. |
| `GET` | `/api/products?categoryId=...&onlyAvailable=true` | Товары с опциональной фильтрацией. |
| `GET` | `/api/products/:id` | Информация по конкретному товару. |
| `GET` | `/api/fulfillment-options` | Список пунктов самовывоза и зон доставки. |
| `POST` | `/api/orders` | Создание заказа (корзина, контакты, способ получения). |

### Формат запроса `/api/orders`

```json
{
  "cartItems": [
    { "productId": "coffee-espresso", "quantity": 2 },
    { "productId": "baguette-classic", "quantity": 1 }
  ],
  "customer": {
    "name": "Иван Иванов",
    "phone": "+79990001122",
    "email": "ivan@example.com",
    "address": "г. Москва, ул. Пушкина, д. 5"
  },
  "fulfillmentMode": "delivery",
  "fulfillmentOptionId": "zone-central",
  "comment": "Позвоните за 30 минут"
}
```

Ответ сервера содержит рассчитанную корзину, стоимость доставки и суммарную стоимость. Оплата не производится — статус `paymentStatus` всегда `pending`.

## Запуск

```bash
node src/server.js
```

По умолчанию сервер слушает порт `3000`. Можно задать `PORT=8080` для запуска на другом порту.

## Интеграция с MODX

1. **Источник данных**. Замените содержимое файлов в `src/data/` на выгрузку из базы MODX или подключите собственный источник.
2. **Авторизация**. При необходимости добавьте проверку токенов или ключей API внутри обработчиков запросов.
3. **Уведомления**. После успешного создания заказа отправляйте письмо, сообщение в Telegram или создавайте запись в MODX через процессоры.
4. **Дальнейшее развитие**. Реализуйте сохранение заказов в базе данных, push-уведомления и отдельное админ-приложение для обработки заказов.

## Проверка

### Встроенный веб-интерфейс

После запуска сервера откройте [http://localhost:3000](http://localhost:3000) — появится тестовое приложение с:

- выбором категорий и товаров;
- корзиной с пересчетом стоимости;
- формой оформления заказа, переключением между самовывозом и доставкой и автоматическим подсчетом доставки.

Приложение отправляет запросы на REST API и отображает ответ. Так можно быстро проверить интеграцию и показать рабочий сценарий коллегам.

### Ручные запросы

Дополнительно можно проверить API через `curl`:

```bash
curl http://localhost:3000/api/categories
```

```bash
curl -X POST http://localhost:3000/api/orders \
  -H "Content-Type: application/json" \
  -d '{
        "cartItems": [{"productId": "coffee-espresso", "quantity": 2}],
        "customer": {"name": "Иван", "phone": "+70000000000"},
        "fulfillmentMode": "pickup",
        "fulfillmentOptionId": "pickup-central"
      }'
```

В ответе будет созданный заказ с расчетами и статусом ожидания оплаты.
